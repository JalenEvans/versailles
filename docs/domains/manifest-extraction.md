# Domain: Manifest Extraction

**Bounded context:** `manifest-extraction`

## Responsibility (what this context owns)

Turning **source code** into the grounding layer for everything downstream — `manifests.json`:

- The field manifest: per-component record of field name → `typeRef`, including nested/related types added transitively to the flat manifest map (build-spec §3.3).
- Structural `sourceHash` computation: hash of **sorted field name+type pairs only**, never the full source file (ADR-0005).
- `typeRef` grammar application: `string | number | boolean | <ComponentName> | list<typeRef> | optional<typeRef> | enum<v1,v2,...>`; TypeScript generics → `list<T>`, literal unions → `enum<...>`.
- The extractor **plugin seam** selected by `config.language` — one of the two pluggable edges (ADR-0008).
- The static-analysis-first policy (ADR-0005): manifests are **never hand-authored, never LLM-authored blind**; LLM assistance is only a verified fallback, checked against real source before writing.
- The permissive typing policy (ADR-0004): inferred/low-confidence fields are flagged and warn, never block.
- The `versailles extract-manifests` command behavior: update entries, preserve entries for components not covered by the current scan, and never prune implicitly (`--prune` only).

## Domain model

**FieldManifest** (entity) — `manifests.json` entry for a component: `sourceHash` + `fields: { name → typeRef }`.

**typeRef** (value object) — the type grammar; the currency of field and param declarations.

**LowConfidenceField** (value object / flag) — a field whose type was inferred, not declared; surfaced as a validator warning.

**ExtractorPlugin** (interface) — the per-language seam. One implementation per source language in v1 (ADR-0009).

**sourceHash** (value object) — the structural hash; recomputable at `versailles check` time for staleness detection.

## Ubiquitous language

Uses from [glossary](../glossary.md): *manifest / field manifest, typeRef, low-confidence field, sourceHash, extractor plugin, component*. A "schema" is a *manifest entry*; a "type string" is a *typeRef*; "diff detection" is *sourceHash staleness*.

## Domain events

- `manifestUpdated` — extractor wrote/updated a component's manifest entry.
- `stalenessDetected` — (with `versailles check`) a recomputed `sourceHash` no longer matches the stored one.

## Relationships

| Relation | Context | Nature |
|---|---|---|
| Downstream of | source code + config | Scans `config.sourceRoots`; the active plugin is chosen by `config.language`. |
| Upstream of | workspace-context | Writes `manifests.json` into the shared workspace; the loader re-parses it on the next load. |
| Upstream of | contract-language | Field resolution and type compatibility read manifests. |
| Upstream of | deterministic-generation | Manifests drive valid-state builders for invariant tests (via the context). |
| Upstream of | external agent (via CLI) | The manifest entry for a component grounds contract authoring by an external agent. |

## Business rules

- Manifests are **derived artifacts** — generated by static analysis, never hand-edited as a source of truth (build-spec §3.3, ADR-0005).
- `sourceHash` covers structural shape only; unrelated changes to method bodies must **not** trigger false staleness (build-spec §7).
- Extraction preserves entries for components not covered by the current scan; removal happens only via `--prune` (build-spec §7).
- Low-confidence inference produces a non-blocking warning, and only high-confidence types participate in hard type-compatibility errors (ADR-0004).
- The core (grammar/validator/generator) must never contain language-specific extraction code — the extractor is a plugin (ADR-0008).

## v1 extractor matrix (ADR-0009)

| Source language | Extractor implementation | Sequencing |
|---|---|---|
| TypeScript | `ts.createProgram` + type checker | **First** |
| C# | Roslyn / source shape analysis | Second |
